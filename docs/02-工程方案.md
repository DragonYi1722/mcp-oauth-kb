## 1. 架构总览

### 1.1 组件与职责

| 组件 | 职责 | 不做什么 |
|---|---|---|
| MCP 客户端 | 发现资源元数据、发起 OAuth、携带 token 调工具 | 不解析业务权限 |
| Keycloak（AS） | 登录、同意、签发/刷新/撤销 token、提供 JWKS | 不存储业务文档 |
| MCP Server（RS） | 验签、校验 aud/iss/scope、工具执行、ACL、审计 | 不签发 token，不把 token 转发给上游 |
| PostgreSQL | 文档、部门、ACL、审计日志 | 不存 token 明文 |
| Caddy | TLS 终止、反向代理 | 不做业务鉴权 |

### 1.2 部署视图

```
                    Internet / Localhost
                             │
                    ┌────────▼────────┐
                    │      Caddy      │  HTTPS, :443
                    └───┬─────────┬───┘
                        │         │
             /mcp       │         │  /realms/*
                ┌───────▼──┐  ┌───▼─────────┐
                │ MCP      │  │  Keycloak   │
                │ Server   │  │  :8080      │
                │ :8000    │  └───┬─────────┘
                └───┬──────┘      │
                    │             │
                ┌───▼─────────────▼───┐
                │   PostgreSQL 16     │
                │   :5432             │
                └─────────────────────┘
```

### 1.3 无状态设计

MCP 2026-07-28 的请求是自包含的：没有 `initialize` 握手、没有 `Mcp-Session-Id`。因此：

- MCP Server 不保存会话状态，可直接起多个副本放在普通负载均衡后面；
- 需要跨调用保持的状态（例如分页游标、草稿）由 **服务端签发 handle**（如 `cursor_id`）或写入数据库；
- 每次请求都携带 `Authorization`、`Mcp-Method`、`Mcp-Name`（工具调用）与 `MCP-Protocol-Version`；
- 反向代理必须原样转发这些头，否则会被 Server 拒绝。

## 2. 关键设计决策（ADR）

| # | 决策 | 备选 | 结论与理由 |
|---|---|---|---|
| ADR-1 | 目标 MCP 2026-07-28 | 2025-11-25 / 2025-06-18 | 选当前规范；无状态、可扩展，作品集差异化 |
| ADR-2 | 官方 `mcp` 2.3 SDK | FastMCP 4 | 授权链路显式可见；FastMCP 仅做对照实验 |
| ADR-3 | Keycloak 作为 AS | Auth0 / 自研 / Google 直连 | 可离线、可 Docker、支持 OIDC/CIMD/联邦 |
| ADR-4 | 预注册 public client 起步 | 直接 CIMD / DCR | 最稳定；CIMD 作为进阶，DCR 已弃用 |
| ADR-5 | scope 绑定 audience | RFC 8707 `resource` | Keycloak 26.7 不校验 `resource`，官方推荐 per-scope mapper |
| ADR-6 | PostgreSQL + pg_trgm | SQLite / 向量库 | 事务与审计需要；中文分词后续接 zhparser |
| ADR-7 | 工具层做 scope/ACL | 只在网关做 | 防止"登录即全权"；权限必须靠近数据 |
| ADR-8 | 身份只取 token `sub` | 入参传 user_id | 杜绝冒充；入参中出现身份字段直接忽略 |

## 3. 授权流程

### 3.1 时序（10 步）

1. 客户端向 `POST /mcp` 发起请求，未带 token；
2. Server 返回 `401`，并带：
   ```
   WWW-Authenticate: Bearer resource_metadata="http://localhost:8000/.well-known/oauth-protected-resource/mcp"
   ```
3. 客户端 GET 该元数据，获得 `authorization_servers: ["http://localhost:8080/realms/kb"]`；
4. 客户端拉取 `http://localhost:8080/realms/kb/.well-known/openid-configuration`（RFC 8414 / OIDC Discovery）；
5. 客户端确定注册方式：预注册 client（本项目默认）；
6. 生成 `code_verifier` / `code_challenge`（S256），跳转授权端点：
   ```
   /realms/kb/protocol/openid-connect/auth
     ?response_type=code
     &client_id=mcp-inspector
     &redirect_uri=http://localhost:6274/oauth/callback
     &scope=openid profile kb.read kb.write
     &code_challenge=...
     &code_challenge_method=S256
     &state=...
   ```
7. 用户在 Keycloak 登录并同意；
8. 客户端用授权码 + `code_verifier` 换 token：
   ```
   POST /realms/kb/protocol/openid-connect/token
   grant_type=authorization_code&code=...&client_id=...&redirect_uri=...&code_verifier=...
   ```
9. 客户端带 `Authorization: Bearer <access_token>` 调工具，同时带 `Mcp-Method: tools/call`、`Mcp-Name: search_documents`；
10. Server 验签并执行；工具层从 token 派生用户，做 ACL 与审计。

### 3.2 受保护资源元数据（Server 必须提供）

`GET /.well-known/oauth-protected-resource/mcp`：

```json
{
  "resource": "http://localhost:8000/mcp",
  "authorization_servers": ["http://localhost:8080/realms/kb"],
  "scopes_supported": ["kb.read", "kb.write", "kb.admin"],
  "bearer_methods_supported": ["header"],
  "resource_documentation": "https://github.com/<you>/mcp-oauth-kb"
}
```

> 生产环境必须使用 HTTPS，且 `resource` 与 token 的 `aud` 完全一致。

两个 SDK 行为（已实测 `mcp==2.3.0`）：

- PRM 路由注册在 **`/.well-known/oauth-protected-resource` + 资源路径**，即 `/.well-known/oauth-protected-resource/mcp`；根路径 `/...` 返回 404。客户端 SDK 会先尝试路径变体，再回退根路径。
- `scopes_supported` 直接取 `AuthSettings.required_scopes`。本项目只把 `kb.read` 列为"进入门槛"，因此 PRM 只声明它；`kb.write` / `kb.admin` 由客户端在授权请求中显式申请，服务端仍在工具层校验 scope 与角色。PRM 未列出不等于不支持。

### 3.3 Access Token 关键 claims

```json
{
  "iss": "http://localhost:8080/realms/kb",
  "sub": "b1f0c6a2-...",
  "aud": ["http://localhost:8000/mcp", "account"],
  "azp": "mcp-inspector",
  "scope": "openid profile email kb.read kb.write",
  "exp": 1760000000,
  "iat": 1760000000,
  "realm_access": { "roles": ["employee"] },
  "department": "engineering",
  "preferred_username": "alice"
}
```

校验规则：

- 验签算法只允许 `RS256`（Keycloak 默认），禁止接受 `none`；
- `iss` 必须等于配置值（逐字符，不要自动补斜杠）；
- `aud` **包含** MCP Server 的规范 URL（数组包含即可，不要求唯一）；
- `exp` 必须存在；`nbf`/`iat` 允许 30 秒时钟偏差；
- `sub` 必须存在，作为唯一用户标识；
- scope 以空格分隔；工具所需 scope 必须全部存在。

### 4.2 分层规则

```
工具层（tools/）        —— 参数校验、scope、审计包裹、错误映射
    ↓
用例层（service.py）    —— 分页、版本冲突、对象级权限判定
    ↓
仓储层（repository.py）—— 内存 / SQL 实现、可见性过滤、连接池
```

- 工具层不得直接拼 SQL；
- 仓储层不得读取 HTTP 请求或 token；
- 所有身份参数由工具层从 token 派生后传入仓储层；
- 审计在工具层通过 `run_audited` 统一包裹，避免每个工具重复实现；
- 对象级越权与「不存在」统一抛 `NOT_FOUND`，不泄露资源是否存在。

## 5. 数据模型

### 5.1 DDL

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE departments (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        TEXT NOT NULL UNIQUE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE users (
    id             TEXT PRIMARY KEY,              -- Keycloak sub
    username       TEXT NOT NULL UNIQUE,
    email          TEXT,
    department_id  UUID REFERENCES departments(id),
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_seen_at   TIMESTAMPTZ
);

CREATE TYPE visibility AS ENUM ('private', 'department', 'org');
CREATE TYPE doc_status AS ENUM ('active', 'archived');

CREATE TABLE documents (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title          TEXT NOT NULL,
    content        TEXT NOT NULL,
    owner_id       TEXT NOT NULL REFERENCES users(id),
    department_id  UUID REFERENCES departments(id),
    visibility     visibility NOT NULL DEFAULT 'department',
    status         doc_status NOT NULL DEFAULT 'active',
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX documents_owner_idx ON documents(owner_id);
CREATE INDEX documents_dept_idx ON documents(department_id);
CREATE INDEX documents_status_idx ON documents(status);
CREATE INDEX documents_title_trgm_idx ON documents USING GIN (title gin_trgm_ops);
CREATE INDEX documents_content_trgm_idx ON documents USING GIN (content gin_trgm_ops);

CREATE TYPE principal_type AS ENUM ('user', 'department', 'role');
CREATE TYPE permission AS ENUM ('read', 'write', 'admin');

CREATE TABLE document_acl (
    document_id     UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    principal_type  principal_type NOT NULL,
    principal_id    TEXT NOT NULL,
    permission      permission NOT NULL,
    PRIMARY KEY (document_id, principal_type, principal_id, permission)
);

CREATE TABLE audit_logs (
    id               BIGSERIAL PRIMARY KEY,
    request_id       TEXT NOT NULL,
    actor_sub        TEXT NOT NULL,
    actor_username   TEXT,
    tool_name        TEXT NOT NULL,
    args_digest      TEXT NOT NULL,          -- SHA-256，不存原文
    result           TEXT NOT NULL CHECK (result IN ('ok', 'denied', 'error')),
    error_code       TEXT,
    duration_ms      INTEGER NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX audit_logs_actor_idx ON audit_logs(actor_sub, created_at DESC);
CREATE INDEX audit_logs_created_idx ON audit_logs(created_at DESC);
```

> 中文检索说明：PostgreSQL 内置分词器不切分中文，MVP 用 `pg_trgm` + `ILIKE` 保证子串可用；进阶可接 `zhparser` 或 pgvector 语义检索。

### 5.2 可见性判定

一篇文档对用户 `u` 可见，当且仅当满足任一条件：

1. `doc.status = 'active'` 且 `doc.owner_id = u.sub`；
2. `doc.visibility = 'org'`；
3. `doc.visibility = 'department'` 且 `doc.department_id = u.department_id`；
4. `document_acl` 中存在 `(user, u.sub, read)` 或 `(department, u.department_id, read)` 或 `(role, any role of u, read)`。

写权限：owner、同部门 manager、admin，或 ACL 中 `write/admin`。

**越权读取统一返回 404**，避免通过 403/404 差异探测文档是否存在。

### 5.3 身份同步

用户的 `sub`、`username`、`department`、`roles` 来自 token。首次调用时 upsert 到 `users`；`department` claim 由 Keycloak 的 user attribute mapper 写入 token。若 claim 缺失，用户只能看到 `private` 与 `org` 文档。

## 6. MCP 工具契约（摘要）

| 工具 | scope | 入参 | 出参 | 幂等 |
|---|---|---|---|---|
| `whoami` | 任意登录 | 无 | `sub/username/roles/scopes/department` | 是 |
| `search_documents` | `kb.read` | `query`, `limit<=50`, `cursor?` | `items[]`, `next_cursor?` | 是 |
| `get_document` | `kb.read` | `document_id` | `document` | 是 |
| `create_document` | `kb.write` | `title`, `content`, `visibility` | `document_id` | 否 |
| `update_document` | `kb.write` | `document_id`, `title?`, `content?`, `visibility?` | `document` | 是（按版本号乐观锁） |
| `archive_document` | `kb.admin` | `document_id`, `reason` | `archived: true` | 是 |

完整 JSON Schema、错误码与示例见 `docs/04-接口与工具.md`。

**身份规则（强制）**：

- 工具入参中不允许出现 `user_id`、`owner_id`、`tenant_id`；出现即忽略并记录告警；
- `owner_id` 一律取 token 的 `sub`；
- 管理员也不能通过入参"代替他人创建文档"，如需代办，使用独立的 `on_behalf_of` 管理工具（不在 MVP）。

**错误码**：

| 码 | HTTP | 场景 |
|---|---|---|
| `UNAUTHENTICATED` | 401 | 无 token / 验签失败 / 过期 |
| `FORBIDDEN_SCOPE` | 403 | 缺少所需 scope |
| `NOT_FOUND` | 404 | 不存在或无权访问 |
| `VALIDATION_ERROR` | 400 | 参数不合法 |
| `CONFLICT` | 409 | 乐观锁版本冲突 |
| `UPSTREAM_UNAVAILABLE` | 503 | JWKS 拉取失败等 |
| `INTERNAL` | 500 | 未预期错误（不泄露细节） |

## 7. Keycloak 配置

### 7.1 Realm 与用户

- Realm：`kb`，`sslRequired: external`；
- 角色：`employee`、`manager`、`admin`；
- 用户：
  - `alice` / `password` / `employee` / department=`engineering`
  - `bob` / `password` / `manager` / department=`engineering`
  - `admin` / `password` / `admin` / department=`it`
- **开发环境专用密码，不得用于生产**。

### 7.2 Client Scope 与 Audience Mapper

为每个权限建一个 client scope，并挂 Audience mapper：

```json
{
  "name": "kb.read",
  "protocol": "openid-connect",
  "attributes": {
    "include.in.token.scope": "true",
    "display.on.consent.screen": "true"
  },
  "protocolMappers": [
    {
      "name": "kb-audience",
      "protocol": "openid-connect",
      "protocolMapper": "oidc-audience-mapper",
      "consentRequired": false,
      "config": {
        "included.custom.audience": "http://localhost:8000/mcp",
        "access.token.claim": "true",
        "id.token.claim": "false",
        "introspection.token.claim": "true"
      }
    }
  ]
}
```

要点：

- **每个 MCP Server 使用独立 scope 名**（本项目 `kb.*`），避免同 realm 多服务串 audience；
- 把三个 scope 设为 client 的 **optional client scopes**，由客户端在授权请求中按需申请；
- Inspector 还会自动申请 `offline_access`（用于刷新令牌），因此两个 client 的 optional scopes 必须包含它，否则 Keycloak 直接返回 `invalid_scope`；同时用户必须拥有 `offline_access` realm 角色，否则登录成功后会报 `Offline tokens not allowed for the user or client`；
- Keycloak 的 client 更新接口**不会**处理 `default/optionalClientScopes` 字段，运行中的 realm 要通过 `/clients/{id}/optional-client-scopes/{scopeId}` 单独添加，realm JSON 只在新建导入时生效；
- client 的 **Full Scope Allowed 保持 `true`**。关闭它时 Keycloak 会丢弃所有未显式授权给 client 的 realm 角色，`realm_access.roles` 为空；工具权限仍由 token 的 `scope` 控制，不依赖该开关；
- `--import-realm` **不会创建 Keycloak 内置 client scope**（`profile`/`email`/`roles`/`basic` 都不存在）。因此 realm JSON 显式定义：
  - `basic`：`oidc-sub-mapper` 提供 `sub`，`oidc-usersessionmodel-note-mapper` 提供 `auth_time`；
  - `kb.profile`：`department`、`preferred_username`、`email` 与 `realm_access.roles` 四个 mapper；
  - 两个 client 的 `defaultClientScopes` 为 `["kb.profile", "basic"]`；
- Keycloak 26.7 对 RFC 8707 `resource` 参数不校验，**不要依赖 `resource` 做 audience 绑定**；服务端仍必须校验 `aud`。

### 7.3 Client

| client_id | 类型 | 用途 | redirect URI |
|---|---|---|---|
| `mcp-inspector` | public + PKCE | Inspector 调试 | `http://localhost:*`、`http://127.0.0.1:*` |
| `mcp-cli` | public + PKCE | Python / TS 客户端 | `http://localhost:8765/callback` |

属性：

```json
{
  "publicClient": true,
  "standardFlowEnabled": true,
  "directAccessGrantsEnabled": false,
  "attributes": {
    "pkce.code.challenge.method": "S256"
  },
  "redirectUris": ["http://localhost:*", "http://127.0.0.1:*"],
  "webOrigins": ["+"]
}
```

生产环境必须收紧 redirect URI 白名单，禁止通配。

### 7.4 Token 生命周期

- Access token：900 秒（15 分钟）；
- SSO session idle：1800 秒；
- 开启 refresh token rotation；
- 关闭 "implicit" 与 "direct access grant"。

### 7.5 CIMD（进阶）

Keycloak 26.6+ 以实验特性提供 CIMD：

```bash
docker run ... quay.io/keycloak/keycloak:26.7.4 \
  start-dev --features=cimd --import-realm
```

需要配置：

1. Client policy profile：包含 `client-id-metadata-document` executor；
2. Client policy：条件为 `client-id-uri`；
3. 按需设置 trusted domains / 是否允许 http（仅本地开发）。

> CIMD 仍标记为 experimental，**不作为 MVP 依赖**。文档中记录"预注册 → CIMD → DCR"的取舍即可。

```python
    jwks_cache_ttl: int = 3600
    database_url: str = "postgresql://kb:kb@localhost:5432/kb"
    required_scope_default: str = "kb.read"

    class Config:
        env_prefix = "KB_"
```

### 8.2 TokenVerifier（核心约 80 行）

```python
import asyncio
import jwt
from jwt import PyJWKClient, PyJWKClientConnectionError, PyJWTError
from mcp.server.auth.provider import AccessToken, TokenVerifier

class KeycloakTokenVerifier(TokenVerifier):
    def __init__(self, issuer: str, resource: str, jwks_uri: str):
        self.issuer = issuer
        self.resource = resource
        self.jwks = PyJWKClient(jwks_uri, cache_keys=True, lifespan=3600)

    async def verify_token(self, token: str) -> AccessToken | None:
        try:
            signing_key = await asyncio.to_thread(
                self.jwks.get_signing_key_from_jwt, token
            )
        except PyJWKClientConnectionError:
            raise  # 网络故障 → 503，而不是当成非法 token
        except PyJWTError:
            return None

        try:
            claims = jwt.decode(
                token,
                signing_key.key,
                algorithms=["RS256"],
                issuer=self.issuer,
                audience=self.resource,
                leeway=30,
                options={"require": ["exp", "iss", "aud", "sub"]},
            )
        except PyJWTError:
            return None

        return AccessToken(
            token=token,
            subject=claims["sub"],
            scopes=claims.get("scope", "").split(),
            expires_at=int(claims["exp"]),
            resource=self.resource,
            claims=claims,
        )
```

### 8.3 组装 Server

```python
from mcp.server import MCPServer
from mcp.server.auth.settings import AuthSettings

mcp = MCPServer(
    "kb",
    token_verifier=KeycloakTokenVerifier(...),
    auth=AuthSettings.model_validate({
        "issuer_url": settings.issuer,
        "resource_server_url": settings.resource_url,
        "required_scopes": ["kb.read"],
        "validate_token_resource": True,
    }),
)
```

注意：

- `validate_token_resource=True` 必须开；
- `audience=` 必须显式传给 `jwt.decode`，SDK 的 `resource_server_url` 不会替你检查 token；
- 不要用 `AnyHttpUrl` 包装 issuer（会补尾部斜杠，导致 issuer 比较失败）；
- `host`/`port`/`transport_security` 在 v2 已移到 `run()` 或 `streamable_http_app()`；
- 默认 DNS rebinding 防护只允许 localhost，公网域名要显式加入 allowlist，否则返回 421。

### 8.4 工具层取身份

```python
from mcp.server.auth.middleware.auth_context import get_access_token

@mcp.tool()
async def whoami() -> dict:
    token = get_access_token()          # 由中间件注入，绝不从入参取
    claims = token.claims
    return {
        "sub": token.subject,
        "username": claims.get("preferred_username"),
        "roles": claims.get("realm_access", {}).get("roles", []),
        "scopes": token.scopes,
        "department": claims.get("department"),
    }
```

### 8.5 scope 校验

```python
def require_scope(token, scope: str):
    if scope not in token.scopes:
        raise ToolError(code="FORBIDDEN_SCOPE", message=f"missing scope: {scope}")
```

- 放在**工具函数第一行**，而不是只依赖 HTTP 中间件；
- `whoami` 不要求额外 scope，只要求已登录；
- 管理工具还要二次检查 `realm_access.roles` 是否包含 `admin`。

### 8.6 请求级审计

用一个装饰器或统一包装：

```python
@audit(tool="search_documents")
async def search_documents(...): ...
```

记录：`request_id`、`sub`、`username`、工具名、参数 SHA-256、结果、错误码、耗时。**不记录 token、正文、密码**。

`request_id` 由 HTTP 中间件生成或复用客户端传入的 `X-Request-ID`，并在响应头回显；`whoami` 也写入审计。查询示例：

```bash
python scripts/audit_report.py --limit 10
python scripts/audit_report.py --user alice --result denied
```

## 9. 客户端实现

### 9.1 MCP Inspector

```bash
npx @modelcontextprotocol/inspector
```

- Transport 选 Streamable HTTP；
- URL：`http://localhost:8000/mcp`；
- 首次连接会收到 401，按提示完成 OAuth；
- 验证 `whoami` → `search_documents` → `get_document`。

### 9.2 Python 客户端（`apps/py-client`）

包名 `kb_client`，命令 `kb-client`，OAuth 不依赖第三方库：

- `oauth.py`：OIDC discovery、S256 PKCE、`state` 校验、loopback `127.0.0.1:8765/callback`、授权码换 token、refresh token 续期；token 缓存到 `~/.kb-client/token.json`（`KB_TOKEN_FILE` 可覆盖），写入后 `chmod 600`；
- `client.py`：`httpx2.AsyncClient` 注入 `Authorization: Bearer`，交给官方 SDK 的 `streamable_http_client`；`ClientSession` 完成 `initialize` / `list_tools` / `call_tool`，优先返回 `structured_content`，`isError` 抛 `ToolFailed`；
- `__main__.py`：`login / tools / whoami / search / get / create / update / archive / call` 子命令；`--token` 与 `KB_ACCESS_TOKEN` 用于 CI。

### 9.3 TypeScript 客户端（`apps/ts-client`）

Node 24 + `@modelcontextprotocol/sdk@1.32.2` + TypeScript：

- `oauth.ts` 与 Python 端同构：discovery、PKCE、loopback server、token 交换与刷新，缓存到 `~/.kb-client/ts-token.json`（`KB_TS_TOKEN_FILE` 可覆盖）；
- `client.ts`：通过 `StreamableHTTPClientTransport` 的 `requestInit.headers` 注入 Bearer token；`callTool` 后按 `structuredContent` / `isError` 归一化；
- `index.ts`：用 `node:util` 的 `parseArgs` 实现同一组子命令；`npm run build` 产出 `dist/`。

> npm 上 SDK 目前仍是 1.32.2，使用 `initialize` 协商，无状态 Server 兼容该旧版客户端；计划中的 `>=2.4`（原生 `server/discover`）发布后可切换。

### 9.4 客户端验收

`scripts/verify_clients.py` 分别启动两个客户端的 `login --no-browser`，读取它们打印的授权 URL，用 `get_token.py` 的 `submit_login_form` 代替浏览器提交 Keycloak 表单，回调落到客户端自己的 loopback server——因此验证的是客户端真实的 discovery、PKCE、`state` 校验与 token 交换。之后调用 `whoami`，把缓存 token 置为过期，再验证 refresh 后仍可调用。2026-11-15 实测 6 项全部通过。

## 10. 部署方案

### 10.1 Docker Compose 服务

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| `postgres` | `public.ecr.aws/docker/library/postgres:16` | 5432 | 挂载 `infra/postgres/init.sql` |
| `keycloak` | `quay.io/keycloak/keycloak:26.7.4` | 8080 | `start-dev --import-realm` |
| `mcp-server` | 本地构建（基于 `public.ecr.aws/docker/library/python:3.13-slim`） | 8000 | 非 root 运行，带 `/healthz` 健康检查 |
| `caddy` | `public.ecr.aws/docker/library/caddy:2` | 443/80 | `public` profile；本地用内部 CA，公网自动签发证书 |

> 国内网络访问 Docker Hub 经常超时（`registry-1.docker.io` 被解析到错误地址）。
> 除 Keycloak 走 `quay.io` 外，官方镜像统一改用 AWS ECR Public 的等价镜像；
> `quay.io` 与 `public.ecr.aws` 均已在本机实测可访问。

### 10.2 环境变量（`.env.example`）

```dotenv
KB_ISSUER=http://localhost:8080/realms/kb
KB_RESOURCE_URL=http://localhost:8000/mcp
KB_JWKS_URI=http://localhost:8080/realms/kb/protocol/openid-connect/certs
KB_DATABASE_URL=postgresql://kb:kb@localhost:5432/kb
KB_STORAGE_BACKEND=memory        # 本地无 Docker 时用内存演示数据
KB_SEED_DEMO_DATA=true
KB_AUTH_ENABLED=false            # 第 4 周改为 true
KB_LOG_LEVEL=INFO
KB_LOG_JSON=false                # 生产可设为 true，输出带 request_id 的 JSON 行
KB_RATE_LIMIT_PER_MINUTE=60      # 每个 sub 每分钟的工具调用预算；0 关闭
KC_BOOTSTRAP_ADMIN_USERNAME=admin
KC_BOOTSTRAP_ADMIN_PASSWORD=admin
POSTGRES_USER=kb
POSTGRES_PASSWORD=kb
POSTGRES_DB=kb
```

Compose 中的 `mcp-server` 服务通过 `environment` 覆盖为
`KB_STORAGE_BACKEND=postgres`，并用 `http://keycloak:8080` 在容器网络内取 JWKS。
`KB_ISSUER` / `KB_RESOURCE_URL` / `KB_JWKS_URI` 可在启动前用同名环境变量覆盖，
公网部署必须把前两者换成外部 HTTPS URL（见 10.4）。

### 10.3 本地启动

```bash
cp .env.example .env
docker compose -f infra/docker-compose.yml up -d postgres keycloak
python scripts/check_keycloak.py --wait 120
python scripts/bootstrap_seed.py --reset   # 用真实 sub 灌用户与 9 篇文档
python scripts/get_token.py                # 浏览器登录 alice/password
KB_AUTH_ENABLED=true KB_STORAGE_BACKEND=postgres python -m kb_mcp.server
python scripts/smoke_auth.py               # 401 / whoami / 部门隔离 / scope 拒绝
python scripts/demo_week5.py               # 三用户可见集合 + 越权用例
```

`check_keycloak.py` 校验 discovery issuer、PKCE S256 与 JWKS 的 RSA 密钥；
`get_token.py` 走完整的授权码 + PKCE 流程并打印 `iss/sub/aud/scope/department/roles`，
加 `--headless --username alice` 可跳过浏览器（仅限本地演示账号）。
`smoke_auth.py` 会登录 alice 与 admin，验证未带 token 返回 401、身份取自 `sub`、
销售部文档返回 `NOT_FOUND`、只读 token 归档返回 `FORBIDDEN_SCOPE`。
这些脚本都只依赖标准库 + `httpx`/`asyncpg`（已在项目依赖中）。

Keycloak 26 的 `start-dev` 不再提供默认 admin，用 Compose 或原生脚本启动时需设置
`KC_BOOTSTRAP_ADMIN_USERNAME` / `KC_BOOTSTRAP_ADMIN_PASSWORD`（默认 `admin`/`admin`）。

若容器镜像拉取失败（国内访问 `quay.io` 可能只有几十 KB/s），可改用官方
Quarkus 发行版直接运行，PostgreSQL 仍留在 Docker 中：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_keycloak_native.ps1
```

发行版可从 Maven 镜像获取（如 `org/keycloak/keycloak-quarkus-dist/26.7.4`），
JRE 可用 Temurin 21。此方式与 `realm-kb.json` 导入、后续 OAuth 流程完全一致。

### 10.4 本地 HTTPS 验证

`public` profile 用 Caddy 内部 CA 提供 TLS，无需域名即可验证代理链路：

```bash
# mcp-server 已在宿主机 :8000 运行
DOMAIN=localhost MCP_UPSTREAM=host.docker.internal:8000 \
  docker compose -f infra/docker-compose.yml --profile public up -d --no-deps caddy

curl -k https://localhost/readyz
curl -k -i -X POST https://localhost/mcp \
  -H 'Content-Type: application/json' -H 'Mcp-Method: tools/list' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
# 期望 401，WWW-Authenticate 带 resource_metadata

docker compose -f infra/docker-compose.yml --profile public rm -sf caddy
```

2026-11-15 实测：证书 issuer 为 `Caddy Local Authority`，`/healthz`、`/readyz` 与
`/mcp` 的 401 + PRM 均正确；另用临时容器设置
`KB_RESOURCE_URL=https://kb.example.com/mcp` 验证 PRM 会返回公网 URL。

### 10.5 公网部署

推荐方案：**Caddy + 域名**（自动 Let's Encrypt），备选 **Cloudflare Tunnel**。

以 `mcp.example.com` 为例：

```bash
DOMAIN=mcp.example.com \
KB_ISSUER=https://mcp.example.com/realms/kb \
KB_RESOURCE_URL=https://mcp.example.com/mcp \
docker compose -f infra/docker-compose.yml --profile public up -d
```

同时必须：

1. 从 `Caddyfile` 删除 `tls internal`，让 Caddy 申请公网证书；
2. Keycloak 设置 `KC_HOSTNAME=https://mcp.example.com` 与 `KC_PROXY_HEADERS=xforwarded`，
   否则它生成的 issuer/授权端点仍是 `http://localhost:8080`；
3. realm 中 `kb.read/write/admin` 三个 Audience mapper 的 audience 改为
   `https://mcp.example.com/mcp`，client 的 redirect URI 收紧到实际地址；
4. 关闭开发用户与默认密码，管理员启用 MFA；
5. 反向代理加请求体上限（如 `request_body { max_size 1MB }`）与访问日志。

> 注意：`realm-kb.json` 目前按本地地址硬编码，公网部署建议复制一份
> `realm-prod.json` 修改 URL 后导入；直接改环境变量不会改 realm 内的 mapper 与 redirect URI。

Cloudflare Tunnel 方式：`cloudflared tunnel --url http://localhost:8000` 只暴露 MCP Server
还不够，Keycloak 的授权端点也必须可达，通常需要两条隧道或同一域名的 path 路由；
TLS 由 Cloudflare 终止时同样要设置 `KC_PROXY_HEADERS`。

## 12. 可观测性

- 审计日志始终结构化：`request_id`、`tool`、`sub`、`result`、`error_code`、`duration_ms`；
- 应用日志默认文本；`KB_LOG_JSON=true` 时输出 `timestamp` / `level` / `logger` / `message` / `request_id`；
- 健康检查：`GET /healthz`（进程存活）、`GET /readyz`（数据库 `ping` 与 JWKS 可用，任一失败返回 503）；
- 限流：`RateLimiter` 按 token `sub` 做 60 秒滑动窗口，默认 60 次/分钟（`KB_RATE_LIMIT_PER_MINUTE`，0 关闭），超限返回 `RATE_LIMITED` 并写审计；计数在进程内，多副本时预算按副本数放大，严格配额需外置到 Redis；
- 指标（进阶）：调用次数、拒绝次数、P95 延迟、JWKS 刷新失败次数；
- 告警（进阶）：连续 401/403 激增、JWKS 拉取失败、审计写入失败。

## 13. 兼容性与已知限制

| 项 | 现状 | 影响 | 应对 |
|---|---|---|---|
| Keycloak RFC 8707 `resource` | 实验特性，默认不启用，且不校验请求值 | 不能依赖 `resource` 绑定 audience | 每个 scope 挂 Audience mapper；服务端强校验 `aud` |
| Keycloak CIMD | 26.6+ 实验特性 | 行为可能变化 | MVP 用预注册 client；CIMD 仅演示 |
| DCR (RFC 7591) | 2026-07-28 已弃用方向 | 旧教程会引导使用 | 文档中说明取舍，不默认启用 |
| MCP `initialize`/Session | 进入废弃期，SDK 保留兼容 | 旧客户端可能仍可用 | 以 `server/discover` 为主；客户端自动协商 |
| PostgreSQL 中文分词 | 内置 parser 不切中文 | 关键词召回差 | MVP 用 pg_trgm；进阶接 zhparser |
| PRM 路由 | SDK 只注册路径变体 `/.../mcp` | 根路径 404，误以为未实现 | 按路径变体验证；客户端 SDK 会自动回退 |
| PRM `scopes_supported` | 只反映 `required_scopes` | 只声明 `kb.read` | 客户端显式申请写/管理 scope；工具层仍强制校验 |
| Claude Desktop 远程连接器 | 由 Anthropic 服务器发起连接，localhost 不可用 | 本地无法直接接入 | 需公网 HTTPS；MVP 以 Inspector 验收，Claude 作为进阶 |
| Keycloak 版本 | 26.7.4 已固定并验证配置；26.8.x 为当前支持线 | 新版本可能有配置差异 | 先按 26.7.4 跑通，再评估升级 26.8.2 |
| SDK API 变动 | Python SDK 2.x 仍在演进；npm TS SDK 最新仅 1.32.2 | 教程代码可能不兼容；TS 端仍走 `initialize` | 锁 `mcp==2.3.0` 与 `@modelcontextprotocol/sdk@1.32.2`；用 `scripts/verify_api.py` 核对 |
