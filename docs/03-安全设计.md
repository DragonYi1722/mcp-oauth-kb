---

## 1. 安全目标与假设

### 1.1 目标

1. **身份可信**：每个请求的用户身份都来自经过验签的 token，不能由调用方自报。
2. **权限最小**：scope 决定"能调哪些工具"，ACL 决定"能看哪些数据"，两者缺一不可。
3. **数据隔离**：用户、部门、全公司三级可见性；越权不泄露文档是否存在。
4. **行为可审计**：每次工具调用可追溯到人、工具、结果与耗时。
5. **令牌可失效**：短 TTL + 刷新轮换 + 撤销，降低泄露后的窗口期。

### 1.2 信任假设

- Keycloak 是可信的授权服务器，其 JWKS 通过 HTTPS 获取；
- MCP Server 的配置（issuer、resource URL、数据库凭据）不被攻击者控制；
- 客户端设备可能被攻破，因此**不信任客户端提交的任何身份字段**；
- 网络默认可被监听，生产环境必须 TLS。

### 1.3 不在范围

- 终端恶意软件、浏览器扩展窃取 token；
- Keycloak 自身 0day；
- 社会工程学与钓鱼；
- DDoS 基础设施防护（仅做应用层限流）。

## 2. 资产与信任边界

| 资产 | 位置 | 机密性 | 完整性 | 可用性 |
|---|---|---|---|---|
| 文档正文 | PostgreSQL | 高 | 高 | 中 |
| 用户身份与部门 | PostgreSQL / Token | 中 | 高 | 中 |
| Access / Refresh Token | 客户端内存/存储 | 高 | 高 | — |
| JWKS 公钥 | Keycloak | 低 | 高 | 高 |
| 审计日志 | PostgreSQL | 中 | 高 | 中 |
| Keycloak 管理员凭据 | 环境变量/密钥库 | 高 | 高 | — |

信任边界：

```
[不可信] 客户端 / 浏览器
    │  TLS + Bearer token
[边界 1] Caddy / 反向代理
    │
[边界 2] MCP Server —— 验签、scope、ACL、审计
    │  参数化 SQL
[边界 3] PostgreSQL
```

跨边界规则：

- 边界 1 之前的所有输入都视为不可信；
- 边界 2 不信任 token 中的业务权限，只信 `sub` 与已验签的 claims；
- 边界 3 只接受参数化查询，不拼接字符串。

## 3. STRIDE 威胁建模

| 类型 | 威胁 | 示例 | 对策 |
|---|---|---|---|
| Spoofing | 冒充用户 | 入参传 `user_id=admin` | 身份只取 token `sub`；忽略入参身份字段 |
| Tampering | 篡改 token | 修改 `sub`/`scope` | RS256 验签；拒绝 `none`；JWKS 缓存 |
| Repudiation | 否认操作 | 用户否认删除文档 | 审计日志（不可由普通用户修改） |
| Information Disclosure | 越权读取 | 读其他部门私有文档 | ACL 过滤；越权返回 404；日志脱敏 |
| Denial of Service | 高频调用 | 每秒 1000 次检索 | 按用户限流；查询超时；分页上限 |
| Elevation of Privilege | 提权 | 用 `kb.read` token 调归档工具 | 工具层 scope 校验 + 角色二次校验 |

## 4. 重点威胁与验证

### T1. Confused Deputy（混淆代理）

**攻击路径**：攻击者诱导高权限的 MCP Server 使用自己的高权限 token 去访问受害者资源，或让 Server 代表攻击者执行管理操作。

**对策**：

- Server 不保存任何"服务账号 token"用于代用户操作；
- 每个请求的身份只来自该请求的 token；
- 工具层 ACL 以 `sub` 为唯一主体；
- 管理工具要求 `kb.admin` scope **且** `admin` 角色。

**测试**：alice（`kb.read/write`）调用 `archive_document` → 期望 `403 FORBIDDEN_SCOPE`；审计记录 `denied`。

### T2. Token Passthrough（令牌透传）

**攻击路径**：Server 把客户端 token 原样转发给上游知识库 API，上游误以为是 Server 自己的凭据，导致权限放大。

**对策**：

- MVP 不调用外部上游 API；
- 若未来接入，使用独立的服务凭据或 RFC 8693 token exchange，绝不复用客户端 token；
- 在出口 HTTP 客户端中禁止自动携带入站 `Authorization`。

**测试**：`test_jku_cannot_redirect_key_lookup_or_forward_the_token` 启动两个本地 JWKS 服务，证明密钥查询只访问配置地址，token 头里的 `jku` 不能改道，且 JWKS 请求不带 `Authorization`。MVP 没有上游 API，因此"透传给上游"这一路径不存在。

### T3. Audience Confusion（受众混淆）

**攻击路径**：攻击者拿到为服务 A 签发的 token，用来调用权限更高的服务 B。MCP Python SDK 曾出现 CVE-2026-116684（未比较 `AccessToken.resource`）。

**对策**：

- `jwt.decode(..., audience=RESOURCE_URL)` 显式校验；
- `AuthSettings.validate_token_resource=True`；
- 每个 MCP Server 使用独立 scope 名与独立 audience；
- 单元测试覆盖"错误 aud"。

**测试**：用 `aud=http://localhost:9999/other` 的 token 调用 → 期望 401。

### T4. PKCE 降级

**攻击路径**：攻击者截获授权码后，用 `plain` 方式或省略 `code_verifier` 换取 token。

**对策**：

- Keycloak client 强制 `S256`；
- 客户端生成高熵 `code_verifier`（43–128 字符）；
- 拒绝缺失 `code_verifier` 的换 token 请求。

**测试**：换 token 时不带 `code_verifier` → 期望 `invalid_grant`。

### T5. Token 重放

**攻击路径**：窃取 token 后在有效期内重复使用。

**对策**：

- Access token 15 分钟；
- Refresh token rotation；
- 支持按用户/会话撤销；
- 高风险操作（归档、批量导出）记录并告警。

**测试**：`test_expired_token_is_rejected` 用本地 RSA 密钥签出过期 token，验签返回 `None`（HTTP 层表现为 401）。Refresh token rotation 已在 realm 中开启（`revokeRefreshToken=true`、`refreshTokenMaxReuse=0`）；会话撤销目前通过 Keycloak 控制台或 Admin API 手动完成，尚无自动化撤销测试。

### T6. 越权 / IDOR

**攻击路径**：修改 `document_id` 读取他人文档。

**对策**：

- 所有查询在 SQL 层附加可见性条件；
- 越权统一返回 404；
- 不返回"无权访问"与"不存在"的差异；
- 分页游标签名，防止篡改。

**测试**：alice 读取 bob 的 private 文档 → 404；日志 `denied`；响应体不含标题。

### T7. SQL 注入

**攻击路径**：在 `query` 或 `title` 中注入 SQL。

**对策**：

- 全部使用参数化查询；
- 禁止字符串拼接 SQL；
- 输入长度限制（query ≤ 512，content ≤ 100 KB）；
- 数据库账号最小权限（仅 DML，无 DDL）。

**测试**：`query="' OR 1=1 --"` → 返回空结果，不报 SQL 错误，不泄露表结构。

### T8. 日志泄密

**攻击路径**：日志中记录完整 token、正文或密码，被运维/第三方日志平台读取。

**对策**：

- 参数只记录 SHA-256 摘要；
- 统一日志过滤器屏蔽 `authorization`、`access_token`、`refresh_token`、`password`；
- 错误响应不返回堆栈。

**测试**：`tests/security/test_audit_redaction.py` 断言审计行只有 32 位摘要，不含 token、正文或标题；JSON 日志格式化后同样不含敏感串。live 测试产生的 token 也用于人工扫描服务端日志（`eyJ` 无命中）。

### T9. CORS / 回调滥用

**攻击路径**：恶意站点使用受害者的授权码回调，或跨域读取响应。

**对策**：

- redirect URI 白名单（生产禁用通配）；
- CORS 仅允许必要 origin 与 `Mcp-Method`/`Mcp-Name` 头；
- 校验 `state`，一次性使用；
- 授权码短有效期（Keycloak 默认 60 秒）。

**测试**：使用 `https://evil.example/cb` 作为 redirect_uri → Keycloak 拒绝；跨域预检只允许白名单。

### T10. 滥用与拒绝服务

**攻击路径**：高频调用检索或提交超长 content。

**对策**：

- 已实现：`RateLimiter` 按 token `sub` 做 60 秒滑动窗口，默认 60 次/分钟（`KB_RATE_LIMIT_PER_MINUTE`，0 关闭），所有工具调用统一计数；
- 已实现：`query ≤ 512`、`content ≤ 100 KB`、`title ≤ 200`、分页 `limit ≤ 50`；
- 部署层：反向代理限制请求体大小；数据库查询超时作为后续加固项。

**测试**：`test_s14_per_subject_rate_limit` 在同一分钟内连续调用 `whoami`，第 61 次返回 `RATE_LIMITED` 并写入 `denied` 审计；`test_s13_oversized_content_is_rejected` 提交 1 MB 正文被拒绝且不落库；`test_ratelimit.py` 覆盖窗口滑动、用户隔离与 0 关闭。

## 5. 认证与授权检查清单

### Keycloak

- [x] `sslRequired=external`（本地 localhost 例外）；
- [x] 关闭 direct access grant 与 implicit flow（两种 client 均为 `false`）；
- [x] public client 强制 PKCE S256；
- [x] redirect URI 白名单；开发环境含 `http://localhost:*`，**生产必须删除通配**；
- [x] 明确 `fullScopeAllowed=true` 的取舍：只为保留 realm 角色，工具权限仍由 scope 决定；
- [x] 每个 scope 配置 Audience mapper，`aud` = MCP Server URL；
- [x] access token 900 秒、`revokeRefreshToken=true`、`refreshTokenMaxReuse=0`；
- [ ] 管理员账号强密码 + MFA（部署前完成）；
- [ ] 开发用户与默认密码不得进入生产（部署前完成）。

### MCP Server

- [x] 只接受 `RS256`，拒绝 `none` / `HS256` / `RS512`；
- [x] 校验 `iss`、`aud`、`exp`、`sub`，时钟偏差 ≤ 30 秒；
- [x] `validate_token_resource=True`；
- [x] scope 校验在工具层；
- [x] 身份只取 `sub`，忽略入参身份字段；
- [x] 越权统一 404；
- [x] 参数化 SQL；
- [x] 输入长度与分页上限；
- [x] 审计日志脱敏；
- [x] 错误响应不泄露堆栈与内部路径；
- [x] 按 `sub` 限流，超限写 `denied` 审计。

### 部署

- [ ] 全链路 TLS；
- [ ] 数据库不暴露公网；
- [x] 密钥通过环境变量注入，`.env` 不提交仓库；
- [ ] 容器以非 root 运行；
- [ ] 依赖锁定并定期扫描（`pip-audit`、`npm audit`）。

## 7. 残余风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| Keycloak 不校验 `resource` | 客户端可申请到含其他服务 aud 的 token | 每个服务独立 scope；服务端强校验 `aud` |
| CIMD 实验性 | 行为可能变化 | 不作为 MVP 依赖 |
| 本地开发明文密码 | 方便演示 | README 明确标注，生产替换 |
| 客户端设备被攻破 | token 可被窃取 | 短 TTL、撤销、设备侧最小权限 |
| 限流仅进程内 | 多副本时每副本各有 60 次/分钟预算 | 需要严格全局配额时改用 Redis；当前单副本演示 |
| 请求体无全局上限 | 1 MB 正文会被字段校验拒绝，但请求仍先被完整解析 | 第 9 周在 Caddy/反向代理加 body size 限制 |
| 令牌撤销为手工流程 | 泄露后需在 Keycloak 控制台/Admin API 撤销会话 | 第 9 周补自动化撤销脚本与演练 |
| 中文检索召回率 | pg_trgm 有局限 | 接受 MVP 限制，进阶接 zhparser/pgvector |

## 8. 事件响应与审计

- 审计日志保留 90 天（演示环境 30 天）；
- 每日检查：401/403 激增、JWKS 拉取失败、审计写入失败；
- 发现泄露时：撤销 Keycloak 会话 → 轮换 client secret（如有）→ 失效 refresh token → 复盘审计日志；
- 所有安全修复在 `docs/03-安全设计.md` 中记录日期、影响范围与验证用例。
