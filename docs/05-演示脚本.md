# 3 分钟演示脚本

## 1. 演示目标

让观众在 3 分钟内看懂三件事：

1. 未登录的 AI 客户端**无法**访问知识库；
2. 登录后，客户端能按用户权限调用工具；
3. 越权行为被**拦截并留痕**。

## 2. 一键预演

录屏前先跑一遍，确认服务端、Keycloak 与种子数据都在位：

```bash
python scripts/demo_portfolio.py
```

它按分镜顺序真实执行：401 + PRM → alice 登录 → `whoami` → 检索 → 新建文档 → 跨部门读取被隐藏 → 只读 token 归档被拒，并提示查看审计日志。
`DEMO_PAUSE=0` 可关闭步骤间停顿，适合 CI；默认停顿 0.8 秒，适合边录边讲。

## 3. 演示前检查清单

- [ ] `docker compose -f infra/docker-compose.yml ps` 显示 postgres、keycloak、mcp-server 均 healthy；
- [ ] Keycloak 控制台 `http://localhost:8080` 可用，realm `kb` 存在；
- [ ] `curl http://localhost:8000/healthz` 返回 200；
- [ ] `curl http://localhost:8000/.well-known/oauth-protected-resource/mcp` 返回正确 JSON；
- [ ] Inspector 已登录，`whoami` 返回 alice；
- [ ] `kb-client whoami` 与 `node dist/index.js whoami` 均可直接用缓存 token 返回 alice（收尾镜头）；
- [ ] 种子数据：engineering 部 5 篇、sales 部 3 篇，其中 1 篇 private；
- [ ] 浏览器无痕窗口准备好（演示未登录状态）；
- [ ] 审计日志查询窗口准备好；
- [ ] 屏幕缩放 125%，终端字号 ≥ 16；
- [ ] 关闭微信/邮件通知。

## 4. 分镜脚本

### 0:00–0:20 开场

**画面**：README 顶部架构图 + 项目名。

**旁白**：
> "这是一个企业知识库 MCP Server。它要解决的问题是：AI 客户端可以自由接入，但每个人的权限必须不一样。为此我用了 MCP 2026-07-28 和 OAuth 2.1。"

### 0:20–0:50 未登录被拒

**画面**：MCP Inspector，连接 `http://localhost:8000/mcp`，直接 `tools/list`。

**期望**：401，`WWW-Authenticate` 指向 PRM。

**旁白**：
> "客户端第一次连接时没有 token，服务端返回 401 和受保护资源元数据，告诉客户端该去哪个授权服务器登录。这就是 RFC 9728。"

### 0:50–1:30 浏览器登录

**画面**：Inspector 弹出授权链接 → 浏览器 Keycloak 登录页 → 输入 `alice/password` → 同意 scope → 回调成功。

**旁白**：
> "登录走的是标准授权码 + PKCE。注意这里申请的是 `kb.read` 和 `kb.write`，没有 `kb.admin`。"

**画面**：调用 `whoami`，展示 `sub`、`department=engineering`、`scopes`。

### 1:30–2:10 正常业务

**画面**：
1. `search_documents(query="复盘")` → 返回 engineering 部文档；
2. `create_document(...)` → 返回新的 document_id；
3. 再次搜索 → 新文档出现。

**旁白**：
> "文档的 owner 不是我传的参数，而是 token 里的 sub。服务端从 token 推导身份，所以伪造 owner 没有意义。"

### 2:10–2:40 越权拦截

**画面**：
1. 读取 sales 部的 private 文档 ID → `NOT_FOUND`；
2. 调用 `archive_document` → `403 FORBIDDEN_SCOPE`；
3. 切到数据库查询 `audit_logs`，展示两条 `denied` 记录（脱敏后）。

**旁白**：
> "越权读取返回 404 而不是 403，避免攻击者探测文档是否存在。所有拒绝都会写审计日志。"

### 2:40–3:00 收尾

**画面**：终端展示 `pytest -m security` 全绿；紧接着 `kb-client whoami` 与 `node dist/index.js whoami` 返回同一个 alice；README 的技术栈与文档链接。

**旁白**：
> "除了 Inspector，Python 和 TypeScript 客户端也各自完成 PKCE 登录，拿到的是同一份身份。项目用 Keycloak 做授权服务器，PostgreSQL 做数据隔离，Docker Compose 一键启动。完整的安全设计和工程方案都在 docs 目录。"

## 5. 备用方案

| 故障 | 处理 |
|---|---|
| Keycloak 登录页打不开 | 切到预录制的 30 秒登录片段 |
| Inspector OAuth 回调失败 | 用 `scripts/get_token.py` 预先取 token，手动填入 Inspector |
| 数据库无数据 | 执行 `python scripts/bootstrap_seed.py --reset` 重新导入 |
| 网络不可用 | 全程本地，提前 `docker compose pull` 缓存镜像 |
| 现场时间不足 | 只演示 0:20–1:30 与 2:10–2:40，其余口述 |

## 6. 录屏建议

- 工具：OBS Studio，1080p 30fps，仅录窗口；
- 终端使用深色主题、字号 18；
- 关键响应体用高亮/放大；
- 旁白先写稿再录，语速控制在每分钟 220 字以内；
- 视频控制在 3 分钟以内，导出 MP4（H.264）。

## 7. 演示后清理

```bash
docker compose -f infra/docker-compose.yml down
```

如需保留数据，去掉 `-v`（默认不删除 volume）。
